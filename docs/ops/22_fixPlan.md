## 一、必须修（A1–A5）

### A1 主表 mAUPR 被任意病灶行污染

- **根因**：长表里 `metric="aupr"` 被所有读者默认为「四类各一行」，新行复用了这个 metric 名。
- **修法**：
  1. 任意病灶用独立的 metric 名 `aupr_any_lesion`（`cls="any"`）。一个 metric 名只承载一种含义。
  2. `retifig.data.seed_table` 取类平均前显式限定 `cls ∈ CLASSES`，作为第二道防线。
- **回归测试**：`test_collect_runs.py` 断言 `metric=="aupr"` 的行恰好是四类，且它们的平均等于评测器的 `summary.mAUPR`。
- **流程上的根因**：这个测试不在 `bench/tests` 里，又依赖 pandas，所以写代码的机器上没人跑。建议把它改成 pytest 能收集的用例，并在 CI 里跑（见第四节）。

### A2 SAM 3 主结果在删图的集合上拼不出来

- **根因**：三个措辞运行各自删图，而下游的拼装还要读这些图。删除权放错了位置。
- **修法**：「最后一个读者负责删除」。
  1. 措辞运行永远不删自己的图；启动器不再给它们传 `--drop-maps`。
  2. 拼装项评测完成后，统一删掉三个措辞目录和自己目录的图，并把各自 done.json 的 `maps_dropped` 置真。
  3. 队列里的措辞运行加 `--no-assemble`，拼装只由闸门项做，保证每个目录只有一个写入者。
  4. 拼装时缺源或源图已丢就抛异常、非零退出；复制先写到 `.partial` 目录再改名，半成品不会被当成完成。
- **回归测试**：FGADR 玩具集上三个措辞运行加拼装，断言 `a_sam3_selected/FGADR` 存在、带池阈值、三个措辞目录的图在拼装之后才消失。

### A3 测试划分静默退成只有固定阈值

- **根因**：池阈值是测试评测的前置条件，但代码把「拿不到」当成合法状态，而且 done.json 一旦写下不再重评。
- **修法**：
  1. 评测层：测试划分拿不到完整池运行的阈值时直接报错（`outputs.thresholds_for_test`）。此时预测已落盘，池运行补齐后重跑只做评测。冒烟（`--limit`）是唯一例外，记为 "fixed only"，反正之后会重做。
  2. 调度层：每个测试项以同来源的池目录为闸门。
  3. `a_sam3_selected` 在池上的拼装标记为测试阶段的前置项，`--test-only` 保留它；测试拼装再以它为闸门。
  4. 闸门改成三态：依赖全部完成为 open；依赖不在本次队列里，或写它的项以非零码退出，为 never（记为失败）；其余为 wait。原来的两态闸门在依赖失败时会让队列永远等下去。
- **回归测试**：先跑测试划分应报错且保留预测；补上池运行后重跑只评测不推理；`--test-only` 的计划里包含两个池拼装项。

### A4 SAM 3 模型留在 CPU（静态判断）

- **根因**：官方 `_setup_device_and_mode` 用字符串比较 `device == "cuda"`；另外 `sam3/model/decoder.py:301` 写死了 `device="cuda"`。这个提交的 SAM 3 实际只支持默认 CUDA 设备。
- **修法**：给构建函数和 `Sam3Processor` 传设备类型字符串；显卡用 `CUDA_VISIBLE_DEVICES` 选（队列本来就这样做）；传 `cuda:1` 这类写法直接拒绝；构建后断言第一个参数所在设备与请求一致。
- **确认方式**：服务器冒烟第一步跑一行 `build_scorer` 加一张 1008 合成图。

### A5 冒烟目录被当成完成

- **根因**：「完成」有两个互不一致的定义（预测看 `limit`，评测只看 done.json 是否存在），而且上游重写后没有让下游失效。
- **修法**：
  1. `is_done(directory, limit)`：完整请求只认完整运行的 done.json；启动器的 `Item.done` 用同一个判断。
  2. `write_predicted` 重写预测时删除同目录的 done.json 和 metrics 文件。上游变了，下游必须失效。
  3. 池的合并直方图不接受带 `limit` 的池运行，所以选择脚本和阈值都不会来自冒烟数据。
- **回归测试**：冒烟后完整运行，断言 done.json 和 metrics.json 的 `n_images` 是全量；冒烟之后启动器的完整计划仍包含该项。

## 二、需要先决定再实现（B1–B6）

这几条都影响预登记内容，应在第一次完整池运行之前定下并提交。

### B1 网格选择规则

- **建议的规则**：每个模型各选一组，`selected: {SAM: {...}, SAM 2: {...}}`。理由：主表里每个训练模型都在验证集上选自己的检查点，SAM 3 逐类选自己的措辞，零样本生成器按同样的原则处理最一致；联合选一组需要再登记一个合并规则，多一个自由度，还会让其中一个模型吃亏。算力不变，每个模型在测试集上仍只跑一个密度。
- **同时登记**：合并方式（建议沿用协议里所有 AUPR 的做法，两个池集按像素合并；要写明这样 DDR 的 149 张占主导）；并列时的取法（建议取较小密度，再取较宽的上限）。
- **实现**：加 `python -m bench.e5.amg --select`，与 SAM 3 的 `--select` 对称：合并两个池集的任意病灶直方图，打印可粘贴的 yaml，六组数字作为注释，同时写一份 `runs/E5/selection_grid.json`（数字、git 提交、池图数）。`selected` 已填时拒绝覆盖。
- **原则**：预登记的选择点不留手工步骤。

### B2 图 5 和表 6 跟上协议

- 零样本一块的主列改为任意病灶 AUPR（`aupr_any_lesion`），训练模型的同一指标作参考线。
- `auto_oracle_class` 移到「上界（读测试真值）」一块。
- SAM 3 一行显式取 `variant="text:selected"`；测试集上最好的措辞只在 5c 里作为上界出现。
- 去掉 `sam3_best` 这种对多个 variant 取最大值的写法。取数函数应当断言每个 (类, 指标) 恰好命中一个 variant，否则报错。
- 小标题改为说明选择来源，例如「Zero-shot (no training; generator setting and wording chosen on 159 validation images)」。
- 占位数据补上新键，并加一个模式测试：图表脚本用到的每个键在 results.csv 里都存在。

### B3 `curve_sets`

建议实现，而非改登记文字：协议已经这样写，且能省掉 FGADR、Retinal-Lesions 三倍的图和评测。
做法是加一个函数 `k_levels_for(frozen, set_name)`（曲线集和池集返回四档，其余只返回 `all`），`prompted.planned` 和 `same_info.planned` 都从它取，启动器自动跟随。测试断言 FGADR 只有 `__kall`。

### B4 算力与预算规则

- 先量再定：冒烟的 predicted.json 里有每窗耗时。建议给启动器加 `--estimate`，按「图数 × 窗口数 × 每窗秒数」给出每项和合计的 GPU 时。
- 把决定前移：现在的预算规则带一句「池结果出来后用户可否决」，这是一条事后分叉。更干净的做法是在池运行之前就定，要么接受 128 的开销，要么把 128 从登记网格里删掉。删掉之后预算规则本身也就不需要了。
- 无论怎么定，collect 都不应让一列无声消失：把 `__fov` 目录收成独立的 test_set（如 `TJDR-uwf (fov)`）并在表注说明，或在缺主变体时显式写一行「未运行（预算规则）」。
- 结论写进 16。

### B5 框的坐标约定

- **建议**：解码器收含端点的像素下标 `[x0, y0, x1−1, y1−1]`。这与 SAM 系「像素下标加 0.5」的约定和 MedSAM 训练时 `np.max` 的取法一致，输入落在模型的训练分布内。
- 提示文件保持右下不含（切片和同信息对照用这个约定是对的），只在解码器边界用一个函数做转换，避免两处各写一遍。
- 在 `e5_frozen.yaml` 的 `oracle.box` 写明约定，predicted.json 记一个约定字段。
- 另一种自洽的选择是传 `[x0−0.5, y0−0.5, x1−0.5, y1−0.5]`（几何上贴着像素边缘）。两者差半个像素，选哪种都可以，关键是登记。
- 必须早于 b 档的池运行，因为池阈值依赖它。

### B6 决定的可追溯性

- 把 D1–D9 的依据写进跟踪的文档，每条一段：背景、备选、决定、谁定的、日期。被跟踪的文档不引用未跟踪的文件；可以加一个小测试，扫描 docs 里出现的仓库路径并核对 `git ls-files`。
- 协议文件的规则与实际做法对齐：把 CHECKPOINT 的表述改成「读到第一个测试指标之后只增不改；之前的修改须在文件头留变更行并同次提交写入 00 和 14」。再进一步可以加哈希锁：冻结后把各节的 sha256 写进锁文件，测试发现改动而锁未更新就失败。
- 合并走 PR，不直接快进推送；PR 描述列出 D1–D9，由 main 的负责人逐条确认。

## 三、工程项

- **内存（amg）**：改成流式累加。每个窗口生成掩码后立刻折进各输出的画布图，再丢弃掩码。面积上限和 oracle_class 都是逐掩码可算的，取最大值满足结合律，结果与现在逐位相同。峰值内存从「整张图的全部掩码」降到「一个窗口的掩码」。加一个测试断言流式与批量结果相等。
- **断点续跑**：以图为单位原子完成。一张图的所有图写完后，往 `progress.jsonl` 追加一行（图 id、窗口数、耗时）；重启时跳过已记录的图；文件用临时名加 `os.replace` 落盘；全部图齐了才写 predicted.json。
- **G2**：16 已经砍掉，建议从三个命令行里删除选项，协议里保留条目并注明未运行。保留一个会和 G1 写同一目录的选项没有好处。
- **提示文件哈希**：运行开始时核对每张图的 `mask_sha256`，不符就报错并提示重新生成。
- **文档**：改正 18 的提交数和「未推送」，删掉 00 里的「待提交」，删掉 18 第八节关于 SAM 2 `min_mask_region_area` 的待验项（登记值是 0，不会进入该路径）。提交清单建议由 `git log` 生成，不手写数量。

## 四、防止同类问题再出现

这次的五个阻断问题里，四个出在已有单元测试的模块之间的接缝上，一个出在没人跑的测试上。对应三条做法：

1. **CI**：GitHub Actions 在每个分支的每次推送上用 CPU 版 torch 跑 `bench/tests` 和 `test_collect_runs.py`。A1 会在推送当时被拦下。
2. **按文档走一遍的端到端测试**：用假模型把 17 第六节的 a–f 步原样执行一遍（冒烟 → 池 → 两处选择 → `--test-only --drop-maps` → collect），断言每个预期目录都完成且阈值正确。A2、A3、A5 都会被它抓到。文档改流程时，这个测试跟着改。
3. **真实模型的契约测试**：在 `server_run.sh check` 里加一组需要权重的用例（没有权重就跳过），三处构建各跑一张合成图，断言输出的形状、类型、取值范围和所在设备。A4 属于这一类。
