四、版本管理（2026-11-10 定）
  1. 数据包有两个号。
       pack id：<设计名>+part<k>，例如 batch01+part1。它是读者答案在浏览器里的钥匙，也写进每个导出文件；同一部分永远不变。pack.json（病例、区域、轮廓、问卷）在同一个 pack id 下也不许变：要改这些，就是新的抽样或新的设计，另起 pack id。
       release：r1、r2、r3……同一个 pack id 的包里任何文件变了（图片、README、阅读工具等）就加 1；新打的包是 r1。release 写在 READ_ME_FIRST.txt 第二行（Pack batch01+part1, release r2, 2026-11-10. Please quote the pack and release when you write to us.）和 zip 文件名里（retiseg_review_batch01_part1_r2.zip，解压后的文件夹名仍是 batch01_part1）。
     build_pack.py：--release（默认 r1）；--clean-existing 必须给 --release，而且要比包里写的更大（没有版本行的旧包算 r1）；同名的 zip 已存在就停，一个 release 只打一次。报告里给出 zip 与 pack.json 的 sha256。
  2. 文档：29 方案、30 指南的版本写在文件开头（vX.Y 与日期）。设计或问卷变了 X 加 1；发出之后的其他改动 Y 加 1；没发出的版本可以原地改。发出的是 PDF，文件名带版本（RetiSeg_protocol_v2.2.pdf、RetiSeg_reader_guide_v2.1.pdf），由仓库里的 md 生成。
  3. 阅读工具（index.html 里的 TOOL_VERSION，现 1.1.0）与问卷（review_schema.json，现 3.1.0）照旧用三段版本号；导出文件记下两者与 pack id，分析按此区分。
  4. 登记：clinical/releases.tsv（进 git）一行一个发出物：日期、名称、版本、文件名、sha256、状态（current 发 / withdrawn 不发）、发给谁（读者编号:日期）。只发 current 的文件；发出后填 sent 列。
  5. 第一部分的现状：r1（服务器打的，带相机元数据）与 11-10 下午的无编号中间版（b6f788c8…）都是 withdrawn；r2（a9c3b09d…）是 current。r2 由 r1 经 --clean-existing --release r2 得到，除 README 的版本行与 SHA256SUMS 外，与中间版逐文件相同；pack.json 与 r1 相同。29 v2.2、30 v2.1 的 PDF 也已生成（各 8 页、6 页，逐页看过）。
