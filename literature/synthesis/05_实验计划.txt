实验计划
接在 01_研究设计 之后。01 定原则，本文件定执行：要补什么、先做什么、每个实验产出哪张图、算力怎么分配。
制定日期 2026-10-02。

零、整篇要回答的三个问题
Q1 复现性：论文汇报的数字，有多少能被作者自己的代码和权重复现？差距多大，来自哪里？
Q2 方法学：在统一数据、统一划分、统一评测下，专用模型是否真的胜过调好的通用基线和基础模型？
    差距是否大于随机种子带来的波动？
Q3 决定因素：数据集、标注粒度、输入分辨率、病灶大小、训练量、损失，哪些真正决定性能？
三个问题分别对应模板论文的“原始模型评测”“重训评测”“影响因素分析”。

一、相对 01 的补充
1. 复现等级。把“可重训/不可重训”细化为五级，每个模型在 meta 末尾记一个等级：
   R0 无代码；R1 只有模型定义；R2 有推理代码和权重；R3 有训练代码；R4 训练代码、权重、划分、环境都齐。
   当前审计结果大致是：M2MRF 为 R4；HACDR-Net、H2Former 为 R3；WSRFNet 为 R1 加邮件索取权重；
   L-Seg 为 R1（Caffe）；SAA、TP-DRSeg 为 R0；其余专用模型 R0。
   这一组数字本身就是论文图 2 的漏斗图。机器可读版本在 bench/configs/models.yaml。
2. 作者联系。所有 R0 到 R2 的专用模型，用固定模板邮件索取代码、权重和划分，统一给 4 周期限。
   回复与否、给了什么，逐条记录在 meta。模板论文的“50 个模型，46 个可测，31 个可重训”就是这样得到的。
3. 轨 C，按论文重写。只重写一小部分高影响、结构描述完整的模型，例如 WSRFNet（已有 model.py，只缺训练循环）、
   L-Seg（Caffe prototxt 移植到 PyTorch）、SAA、RTNet。由另一个 agent 独立完成，交接方式见第七节。
   必须核对参数量与论文一致，结果单独一列，标注“本项目重写”，不和官方代码结果混排。
4. 必须补的基线。
   nnU-Net：医学分割公认的强基线。MICCAI 2024 的 nnU-Net Revisited 表明，很多号称 SOTA 的方法在严格比较下不如它。
     这是回答 Q2 最关键的对照，缺了它审稿人一定会问。
   视网膜领域基础模型：RETFound（Nature 2023，眼底 MAE 预训练 ViT-L）。可选 VisionFM、FLAIR。
     这样基础模型分成“通用自然图像（SAM、SAM 2）”“通用医学（MedSAM）”“眼科专用（RETFound）”三档。
   SAM 3：支持文本概念提示，可以直接测“microaneurysm”“hard exudate”这类文本零样本。
   可选：MedSAM2、DINOv2 或 DINOv3 编码器加统一解码头。
5. 文献补检。现有语料 2025 年以后的模型只有 Chen 2025 一篇。冻结日 2026-09-30 之前需要按固定检索式补检，
   画 PRISMA 流程图：检索数、去重、筛选、纳入，以及每一步排除的理由。
6. 泄漏审计。对应模板论文用 CD-HIT 去掉相似序列。用感知哈希加特征相似度，找出数据集之间和划分之间的近重复图像。
   重点核对：Retinal-Lesions 来自 EyePACS，而 SSMD-UNet 用 EyePACS 无标注数据预训练；
   IDRiD 与 DDR 的分割子集和各自的分级子集是否重叠；同一患者双眼是否跨训练集和测试集。
7. 评测实现审计。已经确认 M2MRF 的 AUPR 实现（mmseg/core/evaluation/my_metrics.py）只用 11 个阈值，
   在阈值 1.0 处把无预测时的精度记为 1，再做梯形积分。WSRFNet 声明沿用这套代码。
   这种实现有偏，方向取决于 PR 曲线形状：弱模型因阈值 1.0 处的锚点被抬高，强模型因梯形积分可能被压低。
   偏差大小要用真实预测图实测，不预设方向。同时 M2MRF 的 tools/prepare_labels.py 把四类合成单标签图，重叠像素按 EX、HE、SE、MA 的顺序覆盖，
   被覆盖的像素在前面那一类里算作阴性。
   用同一批预测图，分别以精确 AP 和各论文的实现计算，并逐项拆开“阈值数”“视野掩码”“标签覆盖”三个来源。
   这一项不需要训练，产出 Extended Data 图。bench/eval/ 已经实现了这三个开关。

二、数据
1. 获取。申请周期最长，本周就发出：
   FGADR 需要签协议申请；e-ophtha 需要向 ADCIS 申请；Retinal-Lesions 需要申请表。
   IDRiD 在 IEEE DataPort；DDR 在百度网盘或 Google Drive；MAPLES-DR 和 DIARETDB1 可直接下载。
2. 统一格式。每张图存三样东西：原分辨率 RGB 图、每类一张二值 mask、视野（FOV）mask。
   扩展标签单独存放。所有划分写成 json 文件，随代码公开。目录约定写在 bench/common/io.py 的文件头。
3. 划分。IDRiD 用官方 54/27；DDR 用官方 383/149/225。IDRiD 没有官方验证集，从训练集固定种子取 10 张。
   FGADR、Retinal-Lesions 按 01 的规定固定种子划分并公开。
4. 预处理。统一流程：按 FOV 裁掉黑边，再缩放到固定的 FOV 直径。主设定和因素实验的分辨率见第四节 E7。
   预测结果一律插值回原分辨率再评测。不少论文在缩小后的分辨率上算指标，这对微动脉瘤的指标影响很大。

三、评测协议（在第一次训练之前冻结，冻结后不改）
参数写在 bench/eval/protocol.yaml。
1. 每个模型只输出原分辨率的逐类概率图，存成 16 位 PNG。所有指标都从概率图离线计算。
   以后增加指标、修正实现，都不需要重训。
2. 主指标：每类在整个测试集上合并像素计算的 AUPR，用精确的逐阈值平均精度（与 sklearn average_precision_score 一致），
   只计 FOV 内像素。四类平均为 mAUPR。e-ophtha 只报 MA 和 EX。
3. 辅指标：Dice、IoU。阈值有两种：固定 0.5，以及在验证集上选出的每类最优阈值。两种都报。
   某一类在某图中没有病灶时，这张图在该类的逐图 Dice 记为缺失，不计 0 也不计 1。
4. 病灶级指标：连通域级检出的精度、召回和 F1；按病灶等效直径相对 FOV 直径分成小、中、大三档，分别计召回率。
   分档边界在拿到数据后，用训练集真值的分布定下来再冻结，不看测试集。
   这对应模板论文按 TCR 数量分析性能，是解释微动脉瘤失败原因的核心证据。ROC 数据集用 FROC。
5. 统计。
   每个重训设定跑 3 个随机种子；IDRiD 训练集小、方差大，跑 5 个。
   报告种子均值和标准差，以及按测试图像 bootstrap 的 95% 置信区间。
   两个模型之间：AUPR 用配对 bootstrap 求差值的置信区间；逐图 Dice 用配对 Wilcoxon 检验，并做 Holm 校正。
   多数据集排名用 Friedman 检验加临界差图。论文汇报排名与我们重训排名的一致性用 Kendall tau。

四、实验矩阵
E0 环境与流水线验证。用 U-Net 在 IDRiD 上跑通“数据、训练、保存概率图、评测”全链路，并记录单次训练耗时。
   第七节的算力估计以这个实测数字为准。

E1 原始模型（轨 A）。对应 Q1 和图 2、图 3。
   M2MRF 的公开权重在 IDRiD、DDR 官方测试集上跑：先用作者评测代码，看能否复现 README 中的数字；
   再用我们的协议评测。两者之差就是实现差异。
   M2MRF README 写明“论文报三次平均，代码只给最好的一次”，这一点要在文中明确交代。
   WSRFNet 等拿到权重后同样处理。SAM2-UNet、SAMed 的公开权重不是本病的，不进轨 A。
   独立测试：所有轨 A 模型再在 MAPLES-DR、e-ophtha 上测。这对应模板论文的独立测试集。

E2 统一重训，数据集内（轨 B）。对应 Q2 和图 4。
   IDRiD、DDR 各训一遍，每个模型多种子。
   设定 B1：统一数据、划分、预处理和评测，损失、优化器、训练步数用作者默认值。这是主表。
   设定 B2：所有模型用同一套训练配方。只在第一层模型上做，用来区分“结构的贡献”和“训练技巧的贡献”。

E3 跨数据集。对应模板论文的未见表位。
   E2 中训练好的模型直接在其余数据集上推理，不需要额外训练。
   另外在 FGADR 上训一组，测细标注集。结果画成训练集乘测试集的矩阵，表头写明细、粗、混合。

E4 标注粒度。在 DDR 上训练，对比只用细标注和混入 FGADR 粗标注；测试固定在 IDRiD、MAPLES-DR 等细标注集。
   用代表模型。

E5 基础模型的四种用法，分开报告。对应图 6。
   a 零样本自动分割：SAM、SAM 2 的自动掩码模式；SAM 3 的文本提示。
   b 理想提示上界：用真值生成框或点作为提示。微动脉瘤一张图可能有上百个，要报告平均每张图需要多少个提示，
     说明这种用法在临床上不现实。
   c 参数高效微调：SAMed（LoRA）、SAM-Adapter、SAM2-UNet。
   d 全量微调或编码器加解码头：MedSAM、RETFound 加 UPerNet 头。

E6 输入信息。仅图像，对比图像加血管图。血管图用公开血管分割模型生成，作为额外通道输入代表模型。
   TP-DRSeg 的图像加文本，如果拿到代码就加入，拿不到只做原文审计。

E7 输入分辨率。FOV 直径 512、1024、1440 三档，代表模型。
   预期微动脉瘤对分辨率最敏感，用病灶大小分层召回来证明。

E8 训练量。DDR 训练集取 10%、25%、50%、100%，画饱和曲线；再加一档 DDR 加 IDRiD 合并训练。
   对应模板论文的数据量饱和分析。

E9 损失。交叉熵、Dice、交叉熵加 Dice、bin loss 或 NALoss。固定结构，只换损失。

E10 计算代价。参数量、FLOPs、训练峰值显存、训练时长、单图推理时间。画性能对代价的散点图。

五、模型分层
第一层，必须完成，进主表：
  通用基线：U-Net、DeepLabv3+、HRNet、nnU-Net、Swin-Unet、FCT
  专用：M2MRF、HACDR-Net、H2Former
  基础模型：SAMed、SAM-Adapter、SAM2-UNet、MedSAM、RETFound 加 UPerNet
第二层，时间允许：UNet++、UPerNet，以及轨 C 交付的 WSRFNet、L-Seg、SAA、RTNet
第三层，只做原文审计：所有 R0 且作者未回复的模型
因素实验 E4、E6、E7、E9 只用代表模型，建议：U-Net、nnU-Net、M2MRF、SAM2-UNet，每族各一个。
集群算力充足时，E7 和 E8 可以扩展到第一层全部模型。

六、代码框架
在项目根目录新建 bench/，与 official_code/ 分开。official_code/ 保持克隆时的原样，不修改。
  bench/common/io.py   数据集目录约定、mask 与概率图读写
  bench/data/          每个数据集一个准备脚本，输出第二节的统一格式和划分 json（待数据到位后写）
  bench/models/        每个模型一个包装文件，从 official_code 引入网络结构，对外统一接口：输入图像，输出逐类 logits
  bench/configs/       models.yaml 是模型登记表（族、层级、复现等级、仓库、轨）；以后每个训练组合一个配置文件
  bench/train.py       统一训练循环，B1 设定下从配置读取作者的损失和优化器（待写）
  bench/predict.py     输出原分辨率概率图（待写）
  bench/eval/          唯一的评测模块，已实现，见下
  bench/tests/         单元测试
  runs/                每次运行一个目录：配置、种子、代码提交号、环境信息、日志、概率图、指标
环境注意：
  RTX 4060 Ti 属于 Ada 架构。M2MRF 原定的 PyTorch 1.6 加 CUDA 10.2 加 mmcv 1.2 在这张卡上基本无法运行，
  集群上的 A100 能跑 CUDA 10.2 以上的版本，但旧版本难以和其他模型共用环境。
  主环境用 PyTorch 2.x 加 CUDA 12.x。基于 mmseg 0.x 的 M2MRF、HACDR-Net，或者打补丁迁移，
  或者另建一个 mmcv-full 1.7 加 PyTorch 1.13 的环境。迁移前后各用作者权重推理一次，确认输出一致。
  本机评测环境：项目内 .venv（Python 3.12，uv 创建），只含 numpy、scipy、scikit-learn、pillow、pyyaml、pytest。

七、算力与分工
可用资源：集群 8 张 A100 40GB；本机 RTX 4060 Ti 16GB。以下是粗估，以 E0 的实测耗时为准修正。
  第一层 E2：约 14 个模型，2 个数据集，3 到 5 个种子，约 100 次训练。
  E4、E6 到 E9：代表模型约 120 次训练，其中不少在 IDRiD 上，单次较短。
  E1、E3、E5a、E5b：只推理。
  合计约 220 次训练。按 A100 单卡单次 3 到 6 小时估，约 700 到 1300 GPU 小时；8 卡并行约 4 到 7 天的纯计算。
  有了 8 卡，瓶颈从算力变成“把每个模型正确接入 bench”的工程时间。
集群与本机的分工：
  集群跑所有训练。默认一次训练占一张卡，8 个任务并行，不做多卡分布式，避免分布式改变 batch 统计和结果。
  只有单卡放不下的模型才用多卡，并在 Supplementary Note 里写明。
  本机做开发、单元测试、评测、作图。
  E10 的推理时间和显存在 A100 上统一测，同时在 4060 Ti 上补测一组，代表普通实验室的条件。
显存：40GB 可以覆盖 SAM ViT-H 的 LoRA 和 RETFound ViT-L 加解码头的微调。
  SAM ViT-H 全量微调在 1024 输入下仍需梯度检查点，如有调整要写进方法部分。
可复现性记录：集群上每个任务记录节点、GPU 型号、驱动、CUDA、PyTorch 版本和随机种子，写进 runs/ 下的运行目录。
轨 C 的交接：
  另一个 agent 只交付网络结构（实现 bench/models/ 的统一接口）、作者训练配方、参数量与论文的核对记录。
  训练、预测和评测走同一套 bench 流程，不另写评测代码。models.yaml 里对应条目的 track 填 C。

十、主要风险
1. 数据申请周期不可控。应对：先发；不依赖 FGADR 的实验先做。
2. 旧代码在新环境下结果漂移。应对：迁移前后用作者权重做数值一致性检查。
3. 集群排队或配额不足。应对：先砍第二层，再把 IDRiD 的种子从 5 降到 3。不砍 nnU-Net，也不砍多种子。
4. 重训结果明显低于原文。这本身就是结论，不是失败。但要排除我们自己的错误：
   先用作者设定复现作者的数字；复现不了，再记为不可复现，并写明尝试过什么。
5. 审稿人质疑“没调超参，不公平”。应对：对第一层每族选一个模型做小规模超参搜索，看排名是否改变。
   模板论文在补充材料里做了同类论证。
