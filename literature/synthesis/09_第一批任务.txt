一、结论
这批可以做，但是经过审计的第一阶段适配配置 benchmark，不是结构优越性的最终结论。当前只跑一套随机种子，即种子 0：8 个模型各在 IDRiD 和 DDR 上训练一次，共 16 个正式任务。登记表里还有 IDRiD 种子 1–4 和 DDR 种子 1–2，这批不提交。
比较的是：数据、划分、视野和评测固定之后，各模型采用来源配方并经过本项目适配之后的整体表现。损失、优化器和训练预算仍是各自来源配方里的数，输入尺寸、头的类型、增强和梯度累积也已经改过。表上的差距是这整套适配配置的差距。不能说差距主要来自结构，也不能据此直接认定专用方法优于通用方法。训练配方统一是 B2，分辨率扫描是 E7。这两项都不作为提交这批的前提，这批也不提前做网格搜索、不增加模型。
论文数字能不能复现，是另一条轨。M2MRF 的作者权重和按作者配方重训已经在 E1、E1r 里，目录与这批分开。已发布权重和某次重训的差值，在没有只改一个因素的对照之前，不归因于批大小。

向导师汇报时，先说这张表比较的是适配后的整体表现，再说下面的限制。这些限制不推翻这批任务，但会改变怎么读结果。

1. 网络实际看到的分辨率并不相同。
   U-Net、DeepLabv3、HRNet、M2MRF、HACDR-Net 看的是裁掉黑边后、长边 1440、保持长宽比的图。
   H2Former 再缩到 960×960，FCT 缩到 384×384，Swin-Unet 缩到 224×224。
   后三个尺寸是结构或作者入口要求的固定输入，配方里写明了。最近邻之后，224 上训练集微动脉瘤连通域消失 16.0%（IDRiD）和 34.3%（DDR），硬性渗出更高，计数在第五节。主表要有一列输入尺寸。224、384、960 和 1440 的平均 AUPR 分开叙述。分辨率本身的实验是 E7，不由这张表代替。

2. 四类病灶的输出语义并不相同。
   U-Net、DeepLabv3、HRNet、FCT、M2MRF 是四路独立 sigmoid，一类一个概率，病灶可以重叠。
   Swin-Unet、H2Former、HACDR-Net 是含背景的互斥 softmax。重叠像素按 EX、HE、SE、MA 的顺序覆盖，后写的留下，所以微动脉瘤优先保留。空像素是背景。
   评测取出的四个概率不再重新归一化。这是作者头的类型，B1 保留它。汇报时把它写成表的一列，避免把两种 AUPR 说成同一个决策。

3. 这张表不回答“能不能复现论文数字”。
   全员训练增强只有水平翻转，概率 0.5。作者流水线里的随机尺度、随机裁剪和光度扰动没有接上。
   M2MRF 作者配置里的翻转概率是 0，这批反而用了 0.5。
   IDRiD 统一重训用 44 张训练图，作者原配方用全部 54 张。那 10 张验证集的名单固定，测试集仍是官方 27 张。
   因此 B1 的绝对数字低于论文是预期中的结果。低于论文时，先读该次运行的 recipe.json 里的偏差清单。已发布权重的精确 mAUPR（IDRiD 0.639，DDR 0.401）和 E1r 里批大小写成 1 的那次重训（IDRiD 0.493）之间还差着增强、裁剪和划分，不能把这个差值写成批大小的效应。批大小对照是正在进行的 E1r bs4，结果出来之前不写原因。

4. 自然图像配方的步数是按原数据集写的，直接搬到 IDRiD 上，更新次数差一个数量级以上。
   DeepLabv3 的 3 万步、名义有效批大小 16 来自 PASCAL VOC。在 IDRiD 的 44 张图上，训练循环每一遍有 3 次更新，图像数是 16、16、12，不是每次都是 16。3 万步就是把这 44 张过一万遍，主数字取最后一步。验证集上更好的检查点另存，不替换主数字。
   Swin-Unet 在 IDRiD 上只有 300 次参数更新，而且每一遍是 24 张和 20 张，不是两次都是 24。方向相反。
   提交范围写在第三节。看到正式测试集之后，不再用测试集改步数、损失或学习率。若要改预算，写成协议修订，并且把旧协议的种子 0 重跑。其余种子不在这批里。

nnU-Net 不在登记的 64 个任务里，也不在当前这 16 个里。05 把它列为必须有的强基线。它有自己的预处理、折和训练计划，塞进这套统一循环会把它变成另一个模型。这套种子看完之后，Q2 的结论句仍留到 nnU-Net 用它自己的入口训完再写。基础模型的四种用法是 E5，也不在这批。

二、这批在整个计划中的位置
三个问题：
Q1 复现性。作者代码和权重能复现论文里的多少。对应轨 A，实验编号 E1。已经完成的是 M2MRF 在 IDRiD 和 DDR 上的作者权重。E1r 是按作者配方重训 M2MRF，正在用有效批大小 4 重跑，目录 runs/E1r_m2mrf_idrid_seed0_bs4。那不是 B1。
Q2 方法学。统一数据、划分和评测之后，方法之间的差距是否大于种子波动。这批是 Q2 的数据集内第一张表，实验编号 E2 的 B1，但只回答适配配置下的整体表现。专用是否优于通用，要等配方统一的 B2 和 nnU-Net，不由这张表单独写成结论。
Q3 决定因素。分辨率、训练量、损失、标注粒度。对应 E4 到 E9，这批不动。E7 不要求在这批之前做完。

模型分三层。这批只含第一层里已经接上统一接口、并且不依赖未到位数据的 8 个：
通用医学分割：U-Net、DeepLabv3、HRNet、Swin-Unet、FCT、H2Former。
眼底专用：M2MRF、HACDR-Net。
H2Former 是多器官的通用医学分割模型。IDRiD 训练脚本只是它的一个入口，DDR 用同一套。不把它算作 DR 专用方法。
第一层里这批没有的：nnU-Net；SAMed、SAM-Adapter、SAM2-UNet、MedSAM、RETFound。
第二层及以后：UNet++、UPerNet、PMCNet、轨 C 的重写模型。Attention-DeepLab 已克隆，尚未冒烟，不升层。

三、任务规模
登记表有 64 个正式任务：8 个模型 ×（IDRiD 五个种子 0–4 + DDR 三个种子 0–2）。当前执行只有一套种子，种子 0，共 16 个：每个模型在 IDRiD 和 DDR 上各一次。IDRiD 的种子 1–4、DDR 的种子 1–2 留在表里，这批不跑。种子均值等以后真的加了种子再算。
冒烟只覆盖这 16 个组合：种子 0、20 个优化器步，目录在 runs/smoke/，不进主表，也不读测试集。HACDR-Net 的 DDR 冒烟要确认交叉熵加 NALoss、通道 (2, 4, 1, 3)、load_from 为空、以及四张概率图能按原图尺寸导出。这些检查同时写在 bench/tests/test_hacdr_recipe.py。NALoss 的构造函数里有 CUDA 张量，没有 CUDA 时 DDR 损失会在建立时失败，不能改成在 CPU 上静默跳过 NALoss。
冒烟通过之后，用 launch_b1.py --submit --seed0 跑这 16 个的全预算。这一波只写训练损失、验证损失、recipe.json 和耗时，不读测试集。确认预算、耗时和实现与登记一致之后，用 --submit --score-seed0 写出这 16 个的测试图。测试图不拿来改配方。--submit --rest 会启动其余 48 个种子，这批不用。--submit 不加波次会拒绝启动全部 64 个。若修改预算，旧协议的种子 0 与当前配方对不上，必须重跑种子 0，再写测试图。
一次任务一张卡，一个进程。8 张 A100 40GB 并行。放不进显存时用梯度累积凑到配方里的有效批大小，不启多卡分布式。BatchNorm 看到的是加载器的批大小，这条写进该次运行的偏差清单。
DeepLab 的 BatchNorm 全程处于评估状态且不更新，因为作者代码要求批大小大于 12 才微调 BatchNorm，而单卡在长边 1440 上放不下 16 张。
M2MRF 的加载器批大小就是 4，与作者 4 张卡、每卡 1 张时同步 BatchNorm 看到的数量相同。

启动：
  python bench/scripts/launch_b1.py
  python bench/scripts/launch_b1.py --smoke
  python bench/scripts/launch_b1.py --submit --smoke
  python bench/scripts/launch_b1.py --submit --seed0
  python bench/scripts/launch_b1.py --submit --rest
  python bench/scripts/launch_b1.py --submit --score-seed0
不加 --submit 只打印命令。--submit 把空闲 GPU 轮流分给这一波的任务。表里的 gpu 字段是 0–7 的占位。当前用 --smoke、--seed0、--score-seed0。--rest 留着不提交。--submit 单独使用会退出，不提交 64 个正式任务。

环境三个，由 bench/scripts/cluster_env.sh 创建，缺权重时训练直接失败，不会静默改成随机初始化：
  retiseg：Python 3.11，PyTorch 2.x，CUDA 12.x。U-Net、DeepLabv3、HRNet、Swin-Unet、FCT、H2Former。
  retiseg-m2mrf：Python 3.7，PyTorch 1.6.0，mmcv-full 1.2.0，mmsegmentation 0.8.0。M2MRF。

五、评测
协议文件 bench/eval/protocol.yaml。2026-10-04 冻结视野规则和分档边界，主表训练开始之后不改这两项。同日补上病灶匹配、阴性图像、缺失标注和 bootstrap 的定义，不改已经冻结的边界数字。
主指标：每类在整个测试集上合并视野内像素的 AUPR，与 sklearn 的 average_precision_score 一致。四类平均为 mAUPR。标签是原始四类掩码。
辅指标：Dice 和 IoU。阈值两种，固定 0.5，以及在验证集上为每类选出的最优阈值。某图没有该类阳性像素时，该图在该类的逐图 Dice 记为缺失，不记为 0。
病灶级：八连通。一个真值病灶只要有任意预测阳性像素重叠就算检出；一个预测连通域只要重叠任意该类真值像素就算真阳性，否则是假阳性。允许多对多，不做一对一匹配，也没有最小 IoU。精度、召回和 F1 在整个划分上合并，不先按图平均。大小用真值病灶的等效直径除以视野等效直径，分档边界仍是 0.005 和 0.011。
阴性图像：该类在视野内没有真值连通域。上面的预测连通域全部计入病灶级假阳性，从而进入精度；它们不进入召回。逐图 Dice 仍是缺失。这些图的阴性像素仍进入 AUPR。
缺失标注：掩码文件不存在就是全负，按阴性图像处理。图像不从划分移除。
统计：种子均值和标准差是另一项汇总。Bootstrap 的单位是测试图像，不是像素，也不是病灶。2000 次有放回抽样，生成器种子 0，每次把抽到的图像直方图合并后重算 AUPR，取 95% 分位区间。某次抽样没有阳性像素则丢掉该次。两个模型的配对 bootstrap 共用同一组图像下标。逐图 Dice 的配对 Wilcoxon 丢掉任一侧缺失的图像对，再做 Holm 校正。种子均值、标准差和逐图 Dice 的 Wilcoxon 要等以后的种子都有 metrics 再做。当前这一套只报种子 0 的点估计，以及该次测试图上按图像的 bootstrap。种子 0 诊断波不跑测试评测。
作者实现的 11 阈值 AUPR 另报，用来解释和论文的差距，不进这张主表。E0 和 E1 已经量过这个差距，见 00。

输入尺寸下病灶是否还在，以及 softmax 覆盖删掉了多少正标签，统计在 bench/eval/input_label_audit.json，由 bench/eval/label_audit.py 从准备好的标注算出，不看模型预测。病灶是视野内的八连通域。消失指最近邻缩放到该网络输入后，这个连通域没有任何像素被采样到。路径与训练相同：先裁视野，长边到 1440，再缩到该网络的固定输入。覆盖规则按 EX、HE、SE、MA 后写覆盖先写，删掉的是训练目标里不再属于该类的阳性像素。评测始终用原始四类标注，不用这张互斥图。下面是训练集。验证集和测试集的同一套计数在 json 里。

六、八个模型各自怎么训
下面的“优化器步”是参数更新次数。累积大于 1 时，一步里会连续做多次小批前向，再更新一次。
加载器不丢掉最后不足一批的图像，凑不满名义有效批的尾部也会更新。尾步的梯度是这几张图的平均，不再除以名义批大小。因此不能把名义有效批写成每一次的实际批大小。recipe.json 的 step_image_counts 记下每一遍的图像数。名义批只等于其中满的那些步。
“遍数”指训练集被完整读过的次数。按 epoch 写预算的模型，遍数就是 epoch 数。按迭代数写预算的模型，遍数是迭代数除以每一遍里的优化器步数；最后一遍若不足，只多读一部分图像。

1. U-Net
   来源：本项目的参考实现，base 32，约 780 万参数，从零训练。没有眼底论文的官方仓库。
   输入：长边 1440。归一化均值和标准差都是 0.5。四路 sigmoid。
   配方：二元交叉熵加 sigmoid Dice，两项权重都是 1；Adam，学习率 1e-4，权重衰减 0；学习率不衰减。有效批大小 4。
   预算：细胞配置写 200 epoch，作为上限。验证损失连续 20 个 epoch 没有更低就停。主检查点是这次最低验证损失。
   IDRiD 最多 2200 步（每 epoch 11 步）。DDR 最多 19200 步（每 epoch 96 步）。
   配方修订和已经看过的测试结果：2026-10-04 的 60 epoch、纯二元交叉熵冒烟，验证损失从 0.591 降到 0.118 仍在下降。这次冒烟的测试精确 mAUPR 0.174（MA 0.002，HE 0.025，EX 0.651，SE 0.018）在修订之前已经看过。加上 Dice、把上限改成 200 epoch、加上 20 epoch 早停，是在看过这个测试数之后做的。该数不进主表，也不能再用来选损失、预算或学习率。此后对本配方的修改只许使用训练损失和验证损失。当前先跑种子 0，用的就是修订后的配方。以后若加种子，也用这一配方。关系写在 U-Net 的 source_of_settings 里。
   IDRiD 每一遍 11 步，每步 4 张。DDR 每一遍 96 步，其中 95 步是 4 张，最后一步是 3 张。

2. DeepLabv3
   登记名是 DeepLabv3，不再用 DeepLabv3+。来源：torchvision 的 deeplabv3_resnet101。骨干 ImageNet-1K。分类头是新建的 4 通道，不加载 VOC 或 COCO 头。
   这个入口是 DeepLabv3：ASPP 加双线性上采样，没有 DeepLabv3+ 的解码器。网络输出步长是 8，论文训练用的输出步长是 16。ASPP 投影的丢弃概率保持 torchvision 的 0.5。TensorFlow 仓库是论文代码，不是这批跑的网络。
   输入：长边 1440。ImageNet 均值和标准差。四路 sigmoid。
   配方：二元交叉熵；SGD，学习率 0.007，动量 0.9，权重衰减 1e-4；poly，幂 0.9。这些数来自 DeepLabv3 的 VOC 训练协议，DeepLabv3+ 论文写明沿用它。论文没有为重叠病灶指定损失，互斥 21 类的交叉熵换成了二元交叉熵。
   预算：3 万个优化器步。加载器批大小 1，名义有效批大小 16。两个数据集都是 3 万步。
   IDRiD 每一遍 3 步，图像数 16、16、12，共一万遍。DDR 每一遍 24 步，其中 23 步是 16 张，最后一步是 15 张，共 1250 遍。满步才是 16 次单张前向。尾步按自己的张数平均。这仍是这批里最贵的一项。
   论文在 VOC trainval 上还有第二阶段 3 万步、学习率 0.001、输出步长 8。B1 没有 trainval 阶段，所以不做第二阶段。随机尺度增强没有接上。

3. HRNet
   来源：官方 HRNet-W48 分割网络，Cityscapes 配置 seg_hrnet_w48_train_512x1024_sgd_lr1e-2_wd5e-4_bs_12_epoch484.yaml。分类头从 19 类改成 4 路 sigmoid。预训练文件 hrnetv2_w48 的 ImageNet 权重，按名称和形状匹配载入。
   输入：长边 1440。ImageNet 均值和标准差。
   配方：二元交叉熵。该 yaml 在 OHEM 关闭时用交叉熵，交叉熵需要互斥类别，而 B1 的标签是四张可重叠的掩码，所以损失记为二元交叉熵。SGD，学习率 0.01，权重衰减 5e-4，动量和 Nesterov 按 yaml。poly，幂 0.9，学习率在更新之后写入，与官方 function.py 一致。
   预算：484 epoch。作者是 4 张卡、每卡 3 张，有效批大小 12。长边 1440 上加载器批大小为 2，累积 6 次。BatchNorm 看到 2 张图。
   IDRiD：1936 步，484 遍。每一遍的图像数是 12、12、12、8。DDR：15488 步，484 遍。每一遍 31 步是 12 张，最后一步是 11 张，因为 383 张里最后一批加载器只有 1 张。
   yaml 里的翻转和多尺度没有接上。官方 drop_last 会丢掉凑不满一个批的图像；这里尾批提交，所以名义有效批 12 不是每一步的实际张数。

4. Swin-Unet
   来源：官方 Swin-Unet，Synapse 入口。5 类 softmax，通道 0 背景，1–4 为 MA、HE、EX、SE。预训练 swin_tiny_patch4_window7_224.pth。
   输入：先做成长边 1440 的视野图，再缩到 224×224。官方 PatchEmbed 要求空间尺寸正好 224。归一化是把像素除以 255，不再减均值。
   配方：0.4×交叉熵 + 0.6×Dice，Dice 的 smooth 为 1e-5，分母用平方和，与官方 utils.py 一致。SGD，学习率 0.01，动量 0.9，权重衰减 1e-4。poly，幂 0.9，学习率在更新之后写入。
   学习率取 train.py 的默认值 0.01。README 和 train.sh 传的是 0.05。config.py 里的 AdamW、5e-4、300 epoch 不被训练循环读取。论文 4.2 节写了批大小 24、动量 0.9 和权重衰减 1e-4，没有写学习率和 epoch 数。
   预算：150 epoch，名义批大小 24。IDRiD 每一遍 2 步，图像数 24 和 20，共 300 次更新。DDR 每一遍 16 步，其中 15 步是 24 张，最后一步是 23 张，共 2400 次更新。两个数据集都是 150 遍。
   重叠像素按第二节的覆盖顺序变成一个类别索引。

5. FCT
   来源：官方 PyTorch 移植，文件是 official_code/FCT/PyTorch/main.py，不是 TensorFlow 入口，也不是本项目另写的网络。本项目的适配是：茎从 1 通道改成 3 通道，四个头通道按顺序改成 MA、HE、EX、SE，视野图再缩到 384。权重 Kaiming normal，无预训练。PyTorch/utils.py 不在仓库里，所以损失和步数是适配配置，写在 author_recipe 里。
   输入：长边 1440 之后再缩到 384×384。论文报告过 224 和 384，取较大的一个。384 能被 32 整除，注意力重排需要正方形。归一化同 Swin-Unet，除以 255。四路 sigmoid。
   配方：二元交叉熵，对应 PyTorch 入口在 sigmoid 之后的 BCE。Adam，学习率 1e-3，权重衰减 0，学习率不变。批大小 4。epoch 数 300，取论文的 50 个 warmup epoch 加随后 250 个；TensorFlow 入口的 120+30 不用。学习率 1e-3 和批大小 4 来自论文实现细节（Synapse、Spleen、ISIC 的批大小）。PyTorch 入口的 utils.py 不在仓库里，超参没有从那个文件读到。
   论文写的交叉熵加 Dice、以及 TensorFlow 三张预测图的加权，这批不用。验证损失平台和 ReduceLROnPlateau 也不用。
   IDRiD：3300 步，约 300 遍，每步 4 张。DDR：28800 步，约 300 遍。每一遍 95 步是 4 张，最后一步是 3 张。

6. H2Former
   归类：通用医学分割，不是 DR 专用方法。来源：官方 idrid_train.py。这是它唯一的眼底训练脚本，DDR 用同一套，不因此变成眼底专用结构。ImageNet ResNet-34。官方发布的 conv1 和 patch embedding 是 4 通道，包装器改成 3 通道后再按名称和形状加载，conv1 对得上。
   输入：长边 1440 之后缩到 960×960。像素保持 0–255 的数值尺度。5 类 softmax。MA、HE、EX、SE 在网络里的通道是 3、2、1、4，与作者脚本的着色一致。
   配方：交叉熵加 Dice，smooth 1e-5，五项（含背景）平均。AdamW，学习率 1e-4，权重衰减 3e-5。poly，幂 0.9，学习率在更新之后写入。批大小 2。92 epoch。
   论文 IV.B 写 90 epoch、批大小 3、权重衰减 1e-4。这批跟训练脚本，不跟论文正文里的另一组数。imgaug 随机裁剪没有接上。
   IDRiD：2024 步，约 92 遍，每步 2 张。DDR：17664 步，约 92 遍。每一遍 191 步是 2 张，最后一步是 1 张。

7. M2MRF
   来源：官方 M2MRF-C，HRNet-W48 骨干，ImageNet 初始化。结构留在 official_code/M2MRF，由 retiseg-m2mrf 环境构建。作者头是四路 sigmoid，通道顺序 EX、HE、SE、MA；前向把它们排列成 MA、HE、EX、SE。重叠不覆盖。
   输入：长边 1440，不缩到作者的裁剪尺寸。IDRiD 作者图像尺度是 (1440, 960)、裁剪 (960, 1440)；DDR 作者是 1024×1024。这批都不用随机裁剪。归一化用作者配置里的 RGB 均值和标准差，换算到除以 255 之后的尺度，仿射变换与作者相同。
   配方：二元 Dice，smooth 1e-5。SGD，学习率 0.01，动量 0.9，权重衰减 5e-4。poly，幂 0.9，最低学习率 1e-4。每卡 1 张、作者启动脚本 4 张卡，有效批大小 4，加载器批大小也是 4。学习率不乘 GPU 数。
   预算：IDRiD 4 万步，每一遍 11 步、每步 4 张，共 3636 遍，末尾再读 16 张。DDR 6 万步，每一遍 96 步，其中 95 步是 4 张、最后一步是 3 张，共 625 遍。主结果用最后一步，不在中途按验证集挑权重。E1 已说明作者 README 报的是最好的一次，论文报三次平均。
   相对作者训练流水线拿掉的部分：缩放到 image_scale、比例范围 (0.5, 2.0) 的随机尺度、随机裁剪、光度扰动。作者翻转概率是 0，这批是 0.5。
   训练脚本 bench/scripts/train_m2mrf_b1.py，评测图由 bench/scripts/predict_m2mrf_b1.py 写出。E1 和 E1r 的目录拒绝覆盖。

8. HACDR-Net
   来源：官方配置 HACDR_idrid.py 和 HACDR_ddr.py。无预训练，load_from 为空。环境 retiseg-hacdr。
   输入：长边 1440。作者裁剪尺寸只记录、不使用：IDRiD (960, 1440)，DDR 1280×1280。归一化是 ImageNet 的 0–255 均值和标准差，同样换算到除以 255 之后。
   头：5 类互斥 softmax。类别顺序来自 FGADRDataset：背景、EX、MA、SE、HE。因此 MA、HE、EX、SE 的通道是 2、4、1、3。重叠规则同第二节。
   配方：AdamW，学习率 6e-5，权重衰减 0.01，betas (0.9, 0.999)。头的学习率倍数 15，位置编码和归一化层的权重衰减倍数为 0。poly，幂 1.0，最低学习率 0。线性 warmup 1500 步，warmup 比例 1e-6。批大小 1。两个数据集都是 4 万步。
   损失按数据集分开，因为作者配置就是这样写的。IDRiD 只有带类别权重的交叉熵，权重 [0.5, 0.7, 1.5, 0.7, 1.1]，对应背景、EX、MA、SE、HE。DDR 在此之上加 NALoss，损失权重 0.2，阈值 0.5，sigma 4。NALoss 的构造函数里有 CUDA 张量，所以 DDR 的损失要在 CUDA 上建立。
   IDRiD 4 万步，批大小 1，共 909 遍，末尾再读 4 张。DDR 共 104 遍，末尾再读 168 张。
   拿掉的作者增强：随机尺度、随机裁剪、光度扰动。水平翻转作者配置也是 0.5，与这批一致。
   训练脚本 bench/scripts/train_hacdr_b1.py。

八、代码怎么串起来
bench/ 与 official_code/ 分开。官方仓库保持克隆时的样子，包装器只导入网络或读取配置。
  bench/configs/b1_frozen.yaml     共享设定：长边、划分、种子数、主指标
  bench/configs/b1_jobs.yaml       登记 64 个正式任务；当前跑其中种子 0 的 16 个，另有 16 个冒烟
  bench/eval/label_audit.py        输入尺寸下的病灶消失和 softmax 覆盖删标
  bench/eval/input_label_audit.json  上述统计
  bench/configs/cells/             每个任务一个细胞配置
  bench/configs/models.yaml        复现等级和分层登记
  bench/data/prepare.py            写出 dataset/prepared/
  bench/data/b1_input.py           读准备好的图、裁视野、归一化、翻转
  bench/models/registry.py         八个包装器的名字
  bench/models/<model>.py          结构、author_recipe、必要时自定义损失和学习率
  bench/runtime.py                 损失、优化器、poly、累积、检查点、运行目录
  bench/train.py                   六个 PyTorch 2 模型的训练和概率图
  bench/scripts/train_m2mrf_b1.py  M2MRF
  bench/scripts/train_hacdr_b1.py  HACDR-Net
  bench/predict.py                 原分辨率 16 位概率图
  bench/eval/                      唯一的评测入口
  bench/scripts/launch_b1.py       打印或提交
  bench/scripts/cluster_env.sh     三个环境
包装器的约定：forward 吃已经归一化、并补齐到 pad_multiple 的张量，返回与输入同空间大小的 logits。author_recipe 只描述优化，不描述裁剪。裁剪和视野由数据模块负责。
冒烟和种子 0 诊断只写训练与验证，不读测试集，也不调用 bench.eval.cli。其余种子的正式命令在训练写完检查点和概率图之后，由 bench.eval.cli 评测主检查点的测试图。种子 0 的测试图在 --score-seed0 里另写。

十、这批故意不做的事
不跑 nnU-Net，原因见第一节。
不跑基础模型的零样本、提示、参数高效微调和全量微调。
不用 FGADR、e-ophtha、Retinal-Lesions。申请还没回。MAPLES-DR 还缺原图。DIARETDB1 的共识规则还没冻结。
不做跨数据集、标注粒度、血管通道、分辨率扫描、训练量比例和损失对照。那些是 E3 到 E9，用这批的检查点或代表模型再做。
不做超参搜索。05 的风险条写明：若审稿人质疑第一轮没调超参，再在每一族里选一个模型做小规模搜索，看排名变不变。那不是这批。
不把 B2 和 E7 提前做完当作这批的前提。当前要确认的是已有任务确实执行登记的实验。
不把作者权重的 mAUPR 和这批的 mAUPR 排进同一列。作者权重、作者配方重训、统一重训分三列。已有权重和重训结果的差值，没有只改批大小的对照时不归因于批大小。

十一、已知的、应当写进补充材料的偏差
每条都会出现在对应运行的 recipe.json。这里是汇报用的汇总。
全员：无随机尺度、无随机裁剪、无光度扰动；视野裁剪加长边 1440；IDRiD 训练 44 张而不是 54 张。
M2MRF：翻转概率从作者的 0 改为 0.5；不使用作者的 image_scale 和 crop_size。
DeepLabv3：登记名是 DeepLabv3，不是 DeepLabv3+。输出步长 8；BatchNorm 冻结；加载器批大小 1，名义批 16，IDRiD 每一遍实际是 16、16、12；损失从互斥类交叉熵改为二元交叉熵；无第二阶段。
HRNet：19 类交叉熵改为 4 路二元交叉熵；BatchNorm 看到 2 张而不是作者同步的 12 张；无翻转和多尺度。
Swin-Unet 与 H2Former、HACDR-Net：互斥标签，覆盖顺序见第二节。
Swin-Unet：学习率 0.01，作者 shell 脚本是 0.05；输入 224。
FCT：网络是官方 PyTorch 移植；本项目适配是 3 通道茎、四类头和 384 输入。损失用代码里的二元交叉熵，论文正文是交叉熵加 Dice；epoch 取论文的 300，不取 TensorFlow 入口的 150。
H2Former：通用医学分割，不是 DR 专用。跟 idrid_train.py（92 epoch，批大小 2，权重衰减 3e-5），不跟论文 IV.B 的另一组数；输入 960；茎从 4 通道改成 3 通道。DDR 用同一脚本。
HACDR-Net：无预训练；IDRiD 与 DDR 的损失不同，与作者两个配置一致。
U-Net：配方是这批的基线设定。Ronneberger 2015 用的是交叉熵。Adam 和 1e-4 来自本项目 E0 的流水线。Dice 项和 200 epoch 上限是在看过 60 epoch 冒烟的测试 mAUPR 之后修订的，见第六节第 1 条。此后只按训练和验证修改。

十二、建议的口头汇报顺序
1. 第一批是经过审计的适配配置 benchmark。当前只跑种子 0 这一套：8 个模型 × IDRiD 和 DDR，16 个正式任务。其余种子留在登记表里，这批不提交。数据只用已经准备好的 IDRiD 和 DDR。
2. 固定的是划分、视野、分辨率上限、评测和种子数。各模型带着来源配方和已经写明的适配。表上的差距是这套整体配置的差距，不是结构优越性，也不是专用方法优于通用方法的结论。
3. 主指标是视野内四类原始标注的 AUPR 平均。病灶匹配、阴性图像误报、缺失标注和按图像 bootstrap 的定义在第五节。论文数字、作者权重、这张表分三列。
4. 先报输入尺寸下的病灶消失和 softmax 删标，再报 sigmoid 与 softmax 两种头、增强少于作者流水线、以及名义批和尾批不一致。DeepLabv3 在 44 张图上每一遍是 16、16、12。
5. 顺序是这 16 个组合的冒烟，然后种子 0 的全预算只看训练和验证，确认后再写这 16 个的测试图。其余种子这批不跑。改预算则重跑种子 0。
6. nnU-Net、B2 和 E7 不在这批的前提里。没有它们，不把“专用模型胜过强基线”写成定论。
7. 已有参照只作背景：M2MRF 已发布权重在 IDRiD 上的精确 mAUPR 是 0.639，在 DDR 上是 0.401。U-Net 的 60 epoch 冒烟测试 mAUPR 是 0.174，已经在修订配方前看过，不进表，也不再用于改配方。它和 0.639 的差不是这批的比较。
